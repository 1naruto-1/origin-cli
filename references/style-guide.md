# 审美规则与理由

这些规则学自用户提供的参考图（`热力图/1–3`、`折线图/1–2`），以及用户明确提出的要求，并已写进 `origin_cli/style.py`、`layout.py` 和 `presets/paper.json`。
本文说明每条规则在解决什么问题。这样遇到规则没覆盖的情况时，你能按同样的思路做决定，而不是机械套用。

## 0. 总原则

**一个维度对应一套视觉通道。** 读者看论文图时，要在几秒内回答两个问题：哪条线是“我的方法”？参数变化时，趋势怎样？因此：
- name（方法）只用**形状**区分（family 模式下还加上**色相**）；
- group（参数）同时用**深浅、大小、填充、线型**四个通道递进。

group 用冗余编码，是为了让黑白打印的版本、色弱的读者，也能分清各组。

**按印刷尺寸设计。** 框的尺寸、字号和线宽都按期刊排版的实际大小设定：框 6.2 × 4.9 cm，字号 7.5–9 pt，线宽 0.37 pt。在 Word 或 LaTeX 里应按 100% 插入。缩放会让线宽和字号偏离设计值，所以需要别的尺寸时，改 `frame` 或预设，不要事后缩放图片。

## 1. 点线图

### 1.1 形状跟着 name 走

顺序为：菱形 → 上三角 → 圆 → 方形 → 下三角 → 六边形 → 五边形 → 星形。

- 前三种在小尺寸下最容易互相区分，参考图也是这三种。
- 方形与菱形只差一个旋转角度，下三角与上三角同理，所以它们排在后面。
- 第 6 种以后，形状已经很难分辨。name 超过 5 个时，建议拆成多个子图，或者只突出重点方法。

### 1.2 group 递进：颜色越深，符号越大、越空

这是参考图里最关键的一条规则，用来保持视觉权重平衡：
- 深色本身就“重”。如果深色符号再大又实心，会把浅色曲线压得看不见。
- 让符号随颜色加深而变大、变空，每条曲线的视觉重量就差不多。
- 空心符号还能让叠在它下面的点露出来；参考图中许多点几乎重合，正好需要这一点。

各项递进的取值：

| 项 | 递进 |
|---|---|
| 大小 | 3 → 4 → 5 → 6 pt（`encode.size`、`size_step`）。参考图里约为 6 → 8 → 10 → 12 px。 |
| 填充（4 组） | 实心 → 上半 → 下半 → 空心 |
| 填充（3 组） | 实心 → 上半 → 空心 |
| 填充（更多组） | 中间依次插入左半、右半、带点 |

中间几组用半填充，是因为它们在视觉上正好介于实心和空心之间。

**未填充的部分是“无填充”，即透明，不是白色**（Origin 里 `Symbol/FillColor = -4`），这是用户的明确要求。参考图中可以看到连线从空心符号中间穿过。如果用白色填充，连线会被切断，叠在下面的点也会被遮住。

另外，连线画在符号后面，并且不在符号处断开（`LineSymbolOrder = 2`）。

### 1.3 线型与线宽

**线型**：用户指定的首选顺序是 Solid → Short Dash → Short Dash Dot → Short Dot，超过 4 组后再用 Dash、Dash Dot、Dot。

优先用“短”线型，是因为相邻两个符号之间的线段很短。长线型的一个周期都放不下，看起来跟实线一样；短线型在短线段上依然认得出来。

**线宽**：默认 0.37 pt，这也是用户指定的。
- 曲线密集时，细线不容易糊成一片；
- 它仍高于多数期刊 0.25 pt 的最低线宽要求。

只有单条曲线、或者需要投影展示时，才考虑加粗到 0.5–0.75 pt。

### 1.4 配色：family 与 group 两种模式

**family（默认，参考“折线图/1”）**：每个 name 一个色系，group 由浅到深。
- 读者用色相认方法，用深浅认参数。
- 适合“几种方法在一组参数扫描下的对比”。

| 色系 | 色值（由浅到深） |
|---|---|
| 蓝 | #B0C4E0 #6C8CB0 #3C5878 #1C304C |
| 红 | #E8C0C0 #D88C8C #A85050 #682C2C |
| 棕 | #D8B08C #A87850 #68482C #3C2C1C |

group 少于 4 个时，取最深的几档。最浅的一档配上 0.37 pt 的细线，印出来太淡。

**group（参考“折线图/2”）**：每个 group 一个色系，name 在色系内由深到浅（排在前面的方法最深）。
- 场景本身是叙事主线时（例如 η = 0.1 / 0.5 / 0.9 下的行为差异）用它，读者先按色相把场景分开。

| 色系 | 色值（由深到浅） |
|---|---|
| 青 | #287070 #289C8C #88B07C |
| 藏青 | #003048 #106480 #209CBC |
| 暖 | #A82C04 #D47C28 #E8A800 |

**categorical**（只有 name 时）：每个 name 取其色系里倒数第二深的一档。
- 各方法的明度相近，不会让某一条线仅仅因为颜色深而显得重要。
- 想突出“我的方法”时，直接给它单独写一个更深的 `color`，比改整套配色更清楚。

### 1.5 图例

| 规则 | 理由 |
|---|---|
| 放在框内，每个子图各一个 | 用户要求。双栏论文版面紧张；而且每个子图单独截出来（放进幻灯片）也能看懂。 |
| 默认底部居中，左右等距 | 用户要求。对称，视觉上安静；很多指标（成功率、准确率）随负载下降，左下角和右下角常是空的。 |
| 避让顺序：先左右小幅平移，再延长纵轴，最后移到顶部 | 用户举的例子是“右边有线就让图例左移一点”。小幅平移几乎察觉不到；延长纵轴会牺牲一点数据的分辨率（参考图数据最低约 0.54，纵轴从 0.45 起）；换到顶部改变了版式，代价最大。 |
| 矩阵排列：每行一个 group，每列一个 name | 和数据的结构一一对应：读者先找参数所在的行，再找方法所在的列。比一长串列表短得多。 |
| 无边框、无底色 | 图例本来就放在空白处，边框只会增加视觉噪声。 |
| 符号样条宽度为 60% 字宽，行距收紧 | 让矩阵图例的宽度与参考图一致，不至于横跨整个框。 |
| 字号 6.5 pt，太宽时自动缩小，最小 5.5 pt | 多数期刊要求成图字号不小于 5–6 pt。 |

### 1.6 坐标轴

- **框与刻度**：四边封闭，刻度朝内，没有次刻度，没有网格。这是工科期刊（IEEE 等）的经典样式，也和参考图一致。网格会和大量曲线、符号互相干扰。
- **横轴留白**：两端各留半个刻度间距（数据 20–90 → 坐标 15–95），首尾两点的符号就不会被框线切掉。
- **纵轴留白**：上下各留约 0.35 个刻度间距；顶端那个 1.0 的点不会贴在框上。
- **刻度值的小数位**：与刻度间距一致（0.05 → 两位）。同一根轴上，各刻度值的位数保持一致。

## 2. 柱状图

- **配色**：规则与点线图相同。柱有边框，深灰色 0.5 pt，这样相邻两根明度相近的柱也能分开。
- **纵轴从 0 开始**：柱子用长度表达数值，截断纵轴会夸大差异。如果数值差异很小、从 0 开始看不出区别，应该改用点线图或断轴，并告诉用户为什么。不要悄悄截断纵轴。
- **overlap 模式**：表达“总量与其中的分量”。大的 group 放在后面、颜色浅，小的放在前面、颜色深，读者能同时看到总量和各分量。这一模式学自 `文献/` 中 Fig.8 的样式。
- **图例**：一般放在顶部，因为底部被柱子占满；自动定位会处理这一点。
- **误差棒**：用边框色，不随柱子的填充色变化，以免浅色柱上的误差棒看不清。

## 3. 热力图

- **两色线性渐变**：同一色相由浅到深，读者自然把它理解为“数值大小”。不要用彩虹色，彩虹色在感知上不均匀，会制造出并不存在的分界。

| 渐变 | 起止色 |
|---|---|
| olive | #EFEB95 → #6E500D |
| green | #CBEF95 → #006100 |
| ocean | #6EFCFC → #004771 |

- **白色细线分格**：分隔各格，又不增加深色笔墨。
- **格内数值**：保留 4 位小数，白字。参考图里，各格之间的差异常常只在第三、四位小数，审稿人会去比这些数。落在渐变最浅端的格子上，白字几乎看不见（参考图恰好没碰到），所以默认对这些格子（与白色对比度低于 1.8）改用深色字，其余保持白字。
- **刻度朝外**：朝内的刻度会盖住色块。
- **色标**：
  - 下限：同一张图的各幅热图共用一个下限（全局最小值向下取整到 0.01）。这样各幅的颜色深浅可以直接比较。
  - 上限：各取本幅的最大值。这样每一幅内部的差异都能用满整个色阶，不会因为某一幅的数值范围小，颜色全挤在一端。参考图三幅的色标正是这样设置的。
  - 刻度：6 个刻度，保留 3 位小数，与参考图一致。
- **色标标题**：竖排在热图与色标之间，与参考图相同，可以省下右侧的宽度。

## 4. 排版与文字

| 项 | 规则 | 理由 |
|---|---|---|
| 西文字体 | Times New Roman | 与期刊正文一致 |
| 中文字体 | 宋体 | 中文期刊和学位论文通用 |
| 字号 | 刻度值 7.5 pt、轴标题 8.5 pt、子图标题 9 pt | 由参考图量得 |

- **中英混排**：中英文混在一起时，工具会自动给中文套上 `\f:宋体()`，不用手写。
- **斜体**：变量用斜体，如 \i(ω)、\i(η)、\i(m)，这是数学排版惯例。单位和下标里的说明性文字用正体，例如 ω<sub>e</sub> 的 e 应写 `\-(e)`，不要写成斜体。
- **多子图排法**：采用“1 + 2”，即 (a) 居中在上，(b)(c) 在下，各框等大。
- **子图标题**：(a)(b)(c) 放在各自横轴标题的下方，居中。

## 5. 学自文献的做法（JSAC 预设等）

`文献/` 里新加的几篇论文中，数据图最讲究的是 Cao 等, IEEE JSAC 2021（Hybrid trusted/untrusted relay QKD）的 Fig.6–10。它们是 Origin 导出的矢量图，颜色、线宽、尺寸都可以从 PDF 里直接读出，`presets/jsac.json` 和 `palettes.json` 的 `categorical.jsac` 就是这样来的。

| 规则 | 理由 |
|---|---|
| Arial，刻度值 6.4 pt、标题 7.2 pt，框 5.07 × 4.1 cm | IEEE 期刊正文是 Times，但图里普遍用无衬线字体，小字号下笔画均匀、更清楚。尺寸按印刷大小量得，插入论文时按 100%。 |
| 刻度朝外，只画下边和左边 | 刻度不压数据点；顶边和右边只留框线，干净。 |
| 浅灰短虚线主网格（#D0D3D4） | 曲线多、读者要比较具体数值时，网格帮助对齐读数；颜色很浅、用虚线，不和数据抢视线。柱状图只画横线，竖线会切过柱子。 |
| 颜色跟着 name（亮色分类配色），两组之间：第一组实心小符号 + 短虚线，第二组空心大符号 + 实线 | 文献 Fig.8/9 里，同一部件在两种方案下同色，读者先按颜色认部件，再按实心/空心、虚线/实线分方案。与 paper 预设的“同色系深浅”相比，这种配色在部件多（6 个）时更好区分。 |
| 图例带细框、白底，放在角上（优先左上） | 这类数据通常随横轴增长、往右上走，左上角是空的。白底盖住网格线，图例更好读。 |
| 两组时排成一列，组右侧用大括号标出组名 | 组名（如 SC CO-QBN、η_r ∈ [1, 2]）较长，放进矩阵式图例的行首会让图例很宽；一列加大括号窄而清楚。避让时只算图例框、括号和组名那几行，空白处不算占用。 |
| 数值上万时刻度值除以 10ⁿ，框左上写 ×10ⁿ | 刻度值只留一两位整数，“3200000” 这样的长数字既占宽度又难读。 |
| 提升百分比用细的双向箭头 + 横排文字 | 文献 Fig.6/10 的写法；箭头两端正好落在要比较的两条曲线上，比端帽括注更直观。 |

其他几篇文献里值得用的做法，作为可选功能加入：

- **柱的花纹**（Yu 等, IEEE Access 2021, RCWA Fig.3–6）：彩色柱上叠一层斜线，黑白打印时靠花纹也能分清方案。`encode.pattern: "diag"`，配 `categorical.access` 配色和虚线框图例。
- **柱线组合的双纵轴**（同一篇 Fig.5）：柱表示一项指标（阻塞率，左轴），线表示另一项（密钥利用率，右轴）；同一算法的柱和线同色，读者能把两项指标对应起来。左右各放一个图例，再用虚线圈 + 箭头指明线条读右轴（`y2.hint`）。这比画两张图更紧凑，适合两项指标有此消彼长关系时。
- **两种量级的断轴柱状图**（Cao 等, JLT 2018, Time-scheduled QKD Fig.19）：ILP 的运行时间在百秒级、启发式在亚秒级，下段 0–0.8 s、上段 150–900 s，跨过断点的柱在断口处断开。这时两段比例尺本来就不同，断点位置不按等比例尺取，默认 0.6。这张图也是“柱子在断口处断开”的一个文献实例。

Cao 等, IEEE ComMag 2018 的图基本是 Origin 默认样式（黑方块、品红圆点等默认颜色序列），杂志排版加了灰底，没有单独学。

## 6. 什么时候偏离

- **用户的明确要求永远优先。** 如果是长期偏好（例如“以后都用 Arial”），新建一个预设，而不是每次都写在 style 里。
- **group 超过 4 个**：填充和线型开始循环，可读性下降。建议拆成多个子图，或改用 group 模式。
- **name 超过 5 个**：形状不好分辨。建议突出 1–2 个重点方法，其余用浅色或细线。
- **期刊有硬性要求**（指定字体、最小线宽 0.5 pt、指定图宽等）：做一个新预设，把要求写进去。
- **数据本身不适合**：例如差异小到柱状图看不出，或数据跨好几个数量级却用线性轴。直接向用户说明，并给出建议（换成点线图、对数轴、断轴），不要用视觉手段掩盖问题。
